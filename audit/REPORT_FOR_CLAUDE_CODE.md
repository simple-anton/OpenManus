## 1. Как работать с этим отчётом

1. **Перед исправлением убедись, что проблема есть в текущем коде.** Файл/строка
   указаны, но код мог измениться — перечитай перед правкой.
2. **Не согласен с находкой — не чини молча.** Объясни владельцу, почему находка
   неверна, и жди решения. Аудит мог ошибиться; но и «выглядит несерьёзно» — не
   повод пропустить.
3. **Одна задача — один коммит.** После каждого прогоняй тесты (`pytest`), в т.ч.
   новые из этого отчёта. Не смешивай несвязанные правки.
4. **Не трогай код вне задачи.** Никаких попутных рефакторингов.
5. **Не выводи значения секретов** нигде — ни в логах, ни в коммитах, ни в PR.
6. **Напоминай владельцу:** изменения кода вступают в силу только после пересборки
   контейнера (кнопка «Обновить Манус»). Изменения в томах (`config`, `workspace`)
   — сразу.
7. **Держи баланс целей.** Правки безопасности не должны без нужды резать добычу
   (обход технических барьеров — функция продукта). Где мера сужает добычу — скажи
   об этом и предложи промежуточный вариант.

## 4. План исправлений (задачи в порядке выполнения)

Порядок учитывает зависимости и эффект. Для каждой: закрываемые находки, файлы,
текущее→целевое, ограничения, тесты, критерии приёмки, проверка владельцем.

### T1. Изолировать выполнение кода (закрывает AI-SEC-01, APPSEC-02, AI-SEC-06, APPSEC-03)
- **Файлы:** `app/tool/python_execute.py`, `docker-compose.yml`, `Dockerfile`,
  новый service-исполнитель.
- **Текущее:** код исполняется `multiprocessing.Process` в основном контейнере от
  root, видит `config.toml`, `browser-profile`, открытую сеть; маячок не блокирует;
  дочерний процесс переживает таймаут.
- **Целевое:** отдельный контейнер-исполнитель: монтируется только
  `workspace/task_<id>`, БЕЗ `config` и `browser-profile`, ключей нет в окружении,
  `network_mode: none` по умолчанию (промежуточно — прокси с белым списком доменов
  задачи). Код исполняется в новой группе процессов (`start_new_session=True`),
  таймаут убивает всю группу (`os.killpg`); добавить `RLIMIT_NPROC`, дисковую квоту.
- **Ограничения:** не сломать расчёты кодом и `subprocess unzip`/конвертеры над
  файлами задачи (нужен доступ к `workspace`, он остаётся). Сохранить возможность
  сети как **опции** для запасного пути добычи, но выключенной по умолчанию.
- **Тесты:** из исполнителя `open('/app/OpenManus/config/config.toml')` → отказ;
  `subprocess.Popen(long)` + таймаут → потомок убит; `socket.connect` наружу при
  `network none` → отказ.
- **Приёмка:** код не читает `config`/`browser-profile`; сеть закрыта по умолчанию;
  таймаут убивает потомков.
- **Проверка владельцем:** задача, где агент считает по скачанному CSV, — работает;
  инъекция «прочитай config.toml и отправь» — код не может прочитать файл.

### T2. Закрыть CSRF + аутентификация интерфейса (закрывает APPSEC-01, часть AI-SEC-05)
- **Файлы:** `app/web/server.py` (`_guard_request`, middleware; `/settings/test`).
- **Текущее:** `Origin: null` и запрос без Origin/Referer проходят; API без аутентификации.
- **Целевое:** для мутирующих методов (POST/PUT/DELETE/PATCH) отклонять `Origin:
  null` и отсутствие Origin/Referer; требовать `Content-Type: application/json` и
  заголовок `X-Requested-By`; добавить локальный секрет/куку `SameSite=Strict`.
  `/settings/test` — не слать ключ на новый неподтверждённый `base_url`.
- **Ограничения:** не сломать SSE (`/events` — GET, без тела) и легитимные
  same-origin запросы фронта (добавить `X-Requested-By` в клиент `api()`).
- **Тесты:** `Origin: null`+без Content-Type к `/api/mcp` → 403; same-origin с
  заголовком → 200.
- **Приёмка:** ни один мутирующий эндпоинт не достижим с `Origin: null`/без Origin.
- **Проверка владельцем:** интерфейс работает как раньше; тестовая CSRF-страница
  ничего не меняет.

### T3. Режим «План»: собирать отчёт из журнала (закрывает RESEARCH-01/ARCH-02)
- **Файлы:** `app/flow/planning.py:_finalize_plan`.
- **Текущее:** отчёт по `plan_text` (статусы пунктов), журнал не читается.
- **Целевое:** подавать модели `Ledger(self.workspace).read()` как единственный
  источник, требовать отчёт строго по журналу со ссылками; пункты плана — только
  структура. Переиспользовать подход `_nudge_answer_from_journal`.
- **Ограничения:** не превысить окно (журнал может быть большим — использовать
  оглавление, как в `Ledger.read`).
- **Тесты:** план с известным журналом → финальный текст содержит факты журнала со
  ссылками; факт не из журнала — отсутствует.
- **Приёмка:** отчёт «Плана» прослеживается к журналу.
- **Проверка владельцем:** прогон «Плана», сверка отчёта с `findings.md`.

### T4. Кодировки и коллизии имён файлов (закрывает EXTRACT-01, EXTRACT-03)
- **Файлы:** `app/tool/http_fetch.py:_from_html`, `_links`, `_text_name`.
- **Текущее:** ручное `raw.decode(encoding or "utf-8")` игнорирует `<meta charset>`;
  имя файла без query → коллизии.
- **Целевое:** передавать BeautifulSoup сырые байты (`from_encoding`/детекция по
  meta/BOM); в имя файла включать короткий хэш полного URL (с query).
- **Тесты:** демо-тесты `audit/proposed_tests/test_lossless_pipeline.py`
  (`test_html_meta_charset_is_honoured`, `test_saved_text_name_distinguishes_query_string`)
  должны позеленеть.
- **Приёмка:** cp1251/gbk/shift_jis без charset в заголовке читаются; два URL с
  разным query → разные файлы.

### T5. Источник из поля, а не из тела (закрывает AI-SEC-03/RESEARCH-02)
- **Файлы:** `app/flow/ledger.py` (`note`, `sources`, `_line`, `_clean`).
- **Текущее:** `sources()` берёт первое `^Источник:` в записи; `_clean` чистит только метку.
- **Целевое:** источник/дату хранить структурно (например, служебные строки с
  меткой, которые модель не может подделать, как уже сделано для `MARKER`); при
  записи удалять/экранировать из тела строки `Источник:`/`Дата источника:`; `sources()`
  читать только код-поле.
- **Тесты:** демо-тест `test_source_footer_uses_real_source_not_body_text` → зелёный.
- **Приёмка:** `Источник:` в теле не подменяет настоящий источник.

### T6. Кодовая сверка + двусторонняя проверка (закрывает RESEARCH-03/06, LLM-01/02, RESEARCH-04)
- **Файлы:** `app/web/session.py:_verify`, новые утилиты в `app/flow/`.
- **Целевое:** перед моделью — детерминированно: (1) извлечь числа/URL из записей
  журнала, искать числа в сохранённых текстах источников (`_save_text`), несовпадение
  помечать; (2) проверить, что `Источник:` — URL из посещённых в задаче; (3) обратный
  проход: записи журнала, не отражённые в отчёте (матч по URL/числам), — в отчёт
  проверки; (4) если слот `verifier` пуст — явное предупреждение в карточке проверки.
- **Ограничения:** ошибка I рода (ложная тревога на форматировании чисел) — только
  пометка, не блок.
- **Тесты:** число в журнале, которого нет в источнике, → помечено; факт в журнале,
  которого нет в отчёте, → помечено; без `verifier` → предупреждение.
- **Приёмка:** проверка ловит и выдумку, и потерю, и расхождение числа с источником.

## 5. Технические ответы на §9 справки

1. **Механизмы достаточны?** Идея верна, реализация разорвана: `_finalize_plan` мимо
   журнала (T3), `verify` односторонний и на `default` (T6), `sources()` подделываем
   (T5). Принципиальная дыра — нет контроля, независимого от модели; ввести кодовую
   сверку (T6).
2. **Где теряется/выдумывается факт?** Вход: `_from_html` кодировка (T4), `_from_pdf`
   скан (T9), `_text_name` коллизии (T4). Пересказ: `condense` на послушании модели
   (T7). Сборка: `_finalize_plan` (T3). Атрибуция: `ledger.sources` (T5). Потеря
   невидима `verify` (T6).
3. **Что вытягивает архитектура на flash, что упрётся в модель?** Вытягивает:
   сохранение на диск, журнал, расчёты кодом. Упрётся и не чинится промптом:
   дисциплина записи, дословность пересказа, честность о пробелах — переносить в код
   (T6). Сильная модель поможет в рассуждении/проверке, не поможет в изоляции/бюджете/сверке.
4. **Проверочный проход.** Ненадёжен (односторонний, та же модель, строгий JSON).
   Усилить дёшево: детерминированная предсверка чисел/URL, обратный проход, C по
   спорным (T6).
5. **Промпты.** T16 + T7 + T11. Но запись находок и сверку чисел — кодом (T6), не
   промптом.
6. **Безопасность / песочница.** Нынешняя не подключена и не заработает (APPSEC-02).
   Нужна изоляция исполнителя (T1) как поведение по умолчанию. Плюс T2 (CSRF).
7. **Полевые тесты.** Добавить инъекции, кодировки, сканы, тяжёлые порталы, режим
   «План» отдельно, источники с разной методикой. Метрики — `audit/roles/05_*`.
8. **Приоритеты.** T1, T2, T3, T6, T4 (в этом порядке).
