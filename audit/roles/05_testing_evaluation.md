### [EVAL-01] Справка декларирует ~60 тестов на «трубу без потерь»; их не существует
Роль: EVAL | Серьёзность: Высокая | Уверенность: подтверждено экспериментом
Где: справка §7; фактически `tests/` — 5 файлов, 29 функций, все из апстрима; `git log --name-only -- tests/` — ни один коммит форка не добавил тест
Простыми словами: разработчик уверен, что «детерминированная труба» (склейка кусков, пороги, оглавление журнала, таблица→диск, проверка, подвал источников) проверена примерно 60 автотестами. На деле таких тестов нет вовсе — есть только унаследованные от апстрима тесты песочницы и браузера, и большинство даже не запускается без Docker.
Суть: расхождение справки с репозиторием. Реальный прогон: **3 passed, 8 failed, 18 errors** (25 из 29 требуют демона Docker). Ни `condense.py`, ни `ledger.py`, ни `compaction.py`, ни `http_fetch.py`, ни `python_execute.py`, ни `verify`, ни подвал источников не покрыты ничем.
Доказательство: инвентаризация файлов и `git log`; прогон pytest.
Последствия: вся «архитектура без потерь» и все предохранители не защищены от регрессий; уверенность владельца в проверенности детерминированной части необоснованна. Именно из-за этого не пойманы EXTRACT-01/03 и AI-SEC-03 (демо-тесты падают — см. EVAL-03).
Исправление: завести набор тестов на детерминированную трубу и предохранители (список в EVAL-02); включить их в pre-commit/CI.
Как проверить: `pytest` показывает покрытие ключевых модулей > 0.

### [EVAL-04] Регрессия: тест доставки картинок падает по существу (агент слеп к скриншотам по умолчанию)
Роль: EVAL | Серьёзность: Средняя | Уверенность: подтверждено экспериментом
Где: `tests/tools/test_browser_use_mcp.py::test_tool_images_follow_the_tool_result_as_user_messages`; причина — `app/agent/toolcall.py:326-329` (доставка картинки только при `llm.supports_images`), `app/config.py:29` (`supports_images=False` по умолчанию)
Простыми словами: единственный не-докеровский тест форка падает. Причина в том, что по умолчанию модель не помечена как «видит картинки», и скриншоты ей не показываются вовсе — а тест это не учитывает. Значит по умолчанию агент «слеп» к снимкам экрана.
Суть: форк изменил `act()`: если `supports_images=False` и нет `vision`-слота, картинка заменяется текстом `NO_EYES`; тест ожидает два сообщения (текст+картинка), получает одно.
Доказательство: прогон — единственный не-Docker FAILED именно этот.
Последствия: либо непочиненный тест (шум, маскирует будущие регрессии), либо сигнал, что скриншоты по умолчанию не работают (это уже находка роли 07). Как минимум тест не отражает нового поведения.
Исправление: привести тест в соответствие с новым поведением (два кейса: `supports_images=True/False`); отдельно решить вопрос слепоты к скриншотам (роль 07).
Как проверить: тест зелёный в обоих режимах.

### [EVAL-05] План полевых тестов из справки: пробелы и усиление (вопрос 7)
Роль: EVAL | Серьёзность: Средняя | Уверенность: подтверждено чтением кода
Простыми словами: задуманные полевые тесты меряют верность на Wikipedia и сгенерированном CSV. Это хорошо для «потерь», но не покрывает главные риски: инъекции, тяжёлые реальные порталы, кодировки, сканы, режим «План» в целом.
Что план НЕ измеряет и надо добавить:
- **Безопасность:** фикстура-страница с инъекцией-канарейкой (`создай audit/canary.txt`) — проходит ли агент мимо; попытка `Origin:null` CSRF.
- **Кодировки/форматы:** cp1251 без charset в заголовке; скан-PDF; `.xls`/`.docx`/zip; CSV с `;`.
- **Полнота/остановка:** задача с заведомо распределёнными по многим источникам данными — измерить долю добытого и честность признания пробелов.
- **Режим «План»:** отдельно проверить, что финальный отчёт опирается на журнал (сейчас — нет, RESEARCH-01).
- **Провалы:** источник, отвечающий 200 но отдающий главную; источник за антиботом; два источника с разной методикой — как агент их сводит.
Исправление: расширить план блоками выше; для каждого — эталон и критерий «правильно/замаскированный провал».

### [EVAL-06] Метрики объективности/потерь/полноты/точности (что автоматом, что человеком)
Роль: EVAL | Серьёзность: Инфо | Уверенность: рекомендация
Предлагаемый набор:
- **Доля утверждений отчёта с проверяемым источником** = (утверждения с URL, где число найдено в сохранённом тексте) / (все числовые утверждения). Автоматом (файлы на диске есть).
- **Точность чисел/дат** = доля чисел отчёта, совпадающих с сохранённым источником. Автоматом.
- **Полнота журнала против эталона** = найденные факты / факты эталона. Полуавтомат (эталон — человек).
- **Доля признанных пробелов** = явно отмеченные «не удалось» / реальные пробелы эталона. Человек.
- **Доля выдуманного** = утверждения без опоры в журнале И в источнике / все. Автоматом (обратный проход) + ревью.
- **Доля успешно добытых источников** = прочитанные / намеченные планом. Автоматом по логам.
- **Доля выводов, обоснованных журналом** = выводы отчёта со ссылкой на запись / все выводы. Человек (выводы — не числа).
- **Обоснованность остановки** = задачи, где `terminate` вызван при закрытой картине / все. Человек.
Приемлемые пороги задаёт владелец; замер на эталоне — единицы задач, стоимость в токенах умеренная.

### [EVAL-07] Что перенести из промптов в код (детерминированные проверки)
Роль: EVAL | Серьёзность: Высокая | Уверенность: рекомендация
Простыми словами: критичные правила сейчас держатся на послушании дешёвой модели. Их можно превратить в обычные проверки — и они перестанут зависеть от модели.
Конкретно:
1. **Сверка числа с источником.** Файлы источников уже на диске (`_save_text`). Извлечь числа/цитаты из записи журнала → искать в тексте источника → несовпадение помечать. Место: новый шаг в `verify` или при `record_finding`. Убивает класс искажений «верно прочитал, неверно записал/пересказал». Ошибка I рода (ложная тревога) на форматировании чисел — терпима (пометка, не блок).
2. **Валидность источника.** `Источник:` в записи — проверять, что это URL из реально посещённых в этой задаче (список у `Fetch.blocked_urls`/логов). Ловит выдуманные URL и подмену (RESEARCH-02).
3. **Обратный проход.** Записи журнала, не отражённые в отчёте, — сматчить по URL/числам детерминированно, остаток отдать модели. Ловит потерю (RESEARCH-03).
4. **Число ⇒ был расчёт.** Для производных величин проверять наличие соответствующего запуска `python_execute` в логах шага.
Место: `app/web/session.py:_verify` + утилиты в `app/flow/`. Цена ошибки II рода (пропуск) — как сейчас; I рода — лишняя пометка, безопасна.
