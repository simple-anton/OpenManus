### Дыра на рубеже 10b (режим «План»)

`app/flow/planning.py:569-587`:

```python
async def _finalize_plan(self) -> str:
    plan_text = await self._get_plan_text()
    system_message = Message.system_message(
        "You are a planning assistant. Your task is to summarize the completed plan.")
    user_message = Message.user_message(
        f"The plan has been completed. Here is the final plan status:\n\n{plan_text}\n\n"
        "Please provide a summary of what was accomplished and any final thoughts.")
    response = await self.llm.ask(messages=[user_message], system_msgs=[system_message])
    return f"Plan completed:\n\n{response}"
```

`plan_text` — это `_generate_plan_text_from_storage()`: список пунктов плана со
значками статуса. `step_notes` остаются пустыми: `_mark_step_completed`
(`planning.py:468-499`) передаёт только `step_status` и **никогда не пишет
notes**. Журнал находок (`findings.md`) в `_finalize_plan` не открывается.

Следствие: итоговая связная часть отчёта в режиме «План» — это пересказ
списка задач со значками ✅/❌, сделанный моделью без единого факта перед
глазами. Всё, что выглядит в нём как данные, модель либо помнит из обучения,
либо домысливает. Это прямо противоречит цепочке «журнал → отчёт», о
достаточности которой спрашивает вопрос 1 справки.

(Оговорка: `Session._flow` склеивает в `last_report` ещё и сырые стенограммы
всех шагов — `result += step_result`. Данные там есть, но в виде
«Step 7: Observed output of cmd …», а не отчёта.)

## 6. Веб-API: поверхность

`app/web/server.py`, единый middleware `guard` (`:249-261`) на все HTTP-запросы.
Аутентификации нет вовсе — доверие тому, кто дотянулся до порта.

Эндпоинты с последствиями за пределами чтения:

| `POST /api/settings` | пишет `config/config.toml`, в т.ч. `llm.base_url` и `api_key` | подмена адреса провайдера |

* обычный кросс-сайт `fetch` с `Origin: https://evil.com` — БЛОКИРУЕТСЯ ✅
* форма с другого сайта (только `Referer`) — БЛОКИРУЕТСЯ ✅
* DNS rebinding (`Host: rebind.evil.com`) — БЛОКИРУЕТСЯ ✅
* **`Origin: null` без `Referer` — ПРОПУСКАЕТСЯ** ❌
* **полное отсутствие `Origin` и `Referer` — ПРОПУСКАЕТСЯ** ❌

Причина в `server.py:80`: условие `if value and value != "null"` намеренно
пропускает строку `null`, после чего цикл не прерывается, `Referer` тоже
отсутствует, и функция возвращает `None` (разрешено). `Origin: null` браузер
шлёт из iframe с атрибутом `sandbox`, из документа `data:` и в ряде
перенаправлений.

## 7. Слоты моделей и стоимость на единицу работы

| Слот | Где используется | Замечание |
|---|---|---|
| `default` | цикл агента, планировщик, `_finalize_plan`, чат | `LLM.isolated()` — свой счётчик на задачу |
| `reader` | `condense()` — пересказ ответов инструментов; `step_digest`, `essence` | до **12 вызовов на один ответ инструмента** (`condense.py:43`), кусками по 40 000 знаков |
| `vision` | описание скриншотов; **работает только если слот задан явно** | `session.py:423-435` |
| `verifier` | проходы B и C | при пустом слоте = `default` |

`max_input_tokens` по умолчанию `None` (`app/config.py:23-26`) → **жёсткого
бюджета токенов нет ни на задачу, ни на установку**. Ограничители только
косвенные: `steps_agent=40`, `steps_plan=20` на пункт, `FLOW_TIMEOUT=3600`
секунд на весь план. Число пунктов плана не ограничено ничем.

## 9. Отличия от апстрима, влияющие на сопровождение

Форк сильно расходится с `FoundationAgents/OpenManus`: удалены Bedrock, MCP-сервер,
`FlowType`; переписаны `toolcall.py`, `base.py`, `schema.py` (`Memory.dropped`),

`app/tool/{http_fetch,journal}.py`. Унаследованные от апстрима и **не тронутые**
места остаются источником риска:

* `app/agent/base.py:165-167` — `handle_stuck_state` **дописывает** текст к
  `next_step_prompt` при каждом срабатывании, промпт растёт неограниченно;
* `app/schema.py:167-171` — `Memory._fit()` режет окно слепым срезом
  `messages[-100:]`, не соблюдая пару «вызов инструмента ↔ его результат»;
* `app/tool/python_execute.py` — изоляция апстрима (её отсутствие) сохранена;
* `app/sandbox/*` — 1300 строк мёртвого кода, требующего docker-сокета.

## 10. Куда, по моей оценке, стоит направить основные силы ролей

1. **Цепочка «недоверенная страница → модель → код от root → тома»** — ничем не
   разорвана; это главный риск всей системы (роли 01, 02).
2. **Подмена источника текстом внутри находки** — бьёт прямо по главному
   обещанию продукта (роли 01, 04).
3. **Режим «План» собирает отчёт мимо журнала** — бьёт по вопросу 1 справки
   (роли 04, 06).
4. **Отсутствие тестов на всю «трубу без потерь»** при том, что справка их
   декларирует (роль 05).
5. **CSRF через `Origin: null` к эндпоинтам, запускающим команды** (роль 02).
6. **Отсутствие бюджета токенов** при пересказе до 12 вызовов на источник (роль 08).
7. **Кодировки, сканированные PDF, архивы, JS-пагинация** — систематические
   провалы добычи (роль 03).
