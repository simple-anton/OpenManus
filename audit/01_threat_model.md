# 01. Модель угроз

Оценка сделана для реальной установки: личный MacBook, Docker Desktop, один
пользователь, управление через браузер. Абстрактные «энтерпрайз»-риски здесь
намеренно не раздуваются, а специфичные для этой установки — усиливаются.

---

## 1. Активы

| Актив | Где лежит | Что значит его потеря |
|---|---|---|
| Ключ API провайдера модели | `config/config.toml` (том), плюс в памяти процесса | траты по счёту владельца без ограничения; pay-as-you-go, фиксированной квоты нет |
| Ключ поискового API (Tavily/Brave/Serper) | там же, раздел `[search]` | то же, меньше масштаб |
| GitHub-токен «магазина навыков» | `config/config.toml`, раздел `[store]` (`app/web/store.py:47-59`) | доступ к репозиториям владельца |
| **Сессии владельца на сайтах** | том `browser-profile` → `/root/.config/chromium` | действия от имени владельца на банковских/платных/личных сайтах, куда он входил руками через noVNC |
| Файлы задач | том `workspace/` | подделка данных исследования |
| Журнал `findings.md` | `workspace/task_*/` | подделка «единственного источника истины» |
| Сервисы на Mac владельца | доступны как `host.docker.internal` | зависит от того, что там слушает |
| **Достоверность отчётов** | результат работы | неверное инвестиционное решение — то, ради чего всё строилось |

## 2. Источники недоверенных данных

Ранжированы по тому, насколько легко противнику ими управлять.

| Источник | Кто управляет | Куда попадает |
|---|---|---|
| Текст страницы после `fetch` | любой владелец сайта | прямо в контекст модели |
| Карта ссылок под страницей (`_links_section`) | тот же | туда же, как «текст → адрес» |
| Страницы, собранные `crawl` | тот же | карта + файлы на диске |
| Сниппеты выдачи `web_search` | владелец сайта + SEO | контекст модели |
| PDF/XLSX/CSV, скачанные `fetch` | владелец сайта | контекст + диск |
| `document.body.innerText` из `browser_exec` | владелец сайта | контекст модели |
| Вывод `python_execute` | код, написанный моделью по прочитанному | контекст модели |
| Ответы внешних MCP-серверов | владелец сервера | контекст модели |
| **`instructions` MCP-сервера** | владелец сервера | **системное сообщение** (`app/agent/manus.py:370-381`) |
| Тело навыка из магазина / zip | автор навыка | системный промпт задачи |
| Файлы в `workspace/` от прошлых задач | прошлый недоверенный контент | журнал, отчёт |

## 3. Граница доверия и «смертельная триада»

Классический критерий: агент опасен, когда одновременно имеет
**(а)** доступ к приватным данным, **(б)** обработку недоверенного контента,
**(в)** канал наружу.

В этой системе выполняются все три, причём в одном процессе:

* **(а)** `config.toml` с ключами и `browser-profile` с сессиями смонтированы
  в тот же контейнер, где выполняется код агента; читаются обычным `open()`.
* **(б)** весь смысл продукта — читать произвольные страницы интернета.
* **(в)** исходящая сеть открыта и для `fetch`, и для `python_execute`, и для
  браузера; дополнительно есть `POST /api/api-tools/test` и сам браузер с
  сессиями владельца как канал.

Триада замкнута полностью. Никакой слой в системе её не разрывает: «маячок
сети» помечает, но не блокирует; песочница не подключена к `python_execute`;
промпт не содержит ни одного правила о недоверенности внешнего текста.

**Вывод для владельца:** любая страница, которую агент откроет, находится в
одном шаге от того, чтобы получить те же права, что есть у самого агента.
Вопрос не «сможет ли инъекция», а «случится ли она».

## 4. Наиболее вероятные сценарии атаки

Упорядочены по произведению «вероятность × ущерб» для этой установки.

### A. Инъекция со страницы → код от root → ключи наружу
Страница, которую агент читает ради данных, содержит текст, адресованный
модели. Модель пишет и выполняет Python, читающий `config/config.toml` и
отправляющий содержимое наружу. Ничто на пути не проверяет ни происхождение
инструкции, ни назначение исходящего соединения.
Усиливающий фактор: системный промпт сам учит модель запускать `subprocess`
(`app/prompt/manus.py:121-137`), так что «напиши код и выполни» — обычное,
ожидаемое поведение, а не аномалия.

### B. Инъекция → долговечная подмена через тома
Тот же путь, но код правит `config/config.toml` (подменяя `llm.base_url` на
адрес противника) или `config/mcp.json` (добавляя stdio-сервер с произвольной
командой). И то, и другое — **тома**, переживают перезапуск и пересборку.
Кнопка «Обновить Манус» вред не снимает.

### C. Инъекция → действия в сессиях владельца
`browser_exec` работает в том же профиле Chromium, где владелец входил руками
через noVNC. Разделение только по вкладкам (`app/web/browser_tabs.py`) и только
на уровне просьбы в промпте («Do NOT manage tabs yourself»). Кроме того, из
`python_execute` доступен CDP на `127.0.0.1:9222` напрямую — это обходит и
вкладочную дисциплину, и `browser_exec` целиком.

### D. CSRF со стороннего сайта в обычном браузере владельца
Проверка `Host`/`Origin` закрывает типовые случаи, но пропускает `Origin: null`
(iframe с `sandbox`, документ `data:`). Цепочка: `POST /api/settings` меняет
`llm.base_url` → `POST /api/settings/test` отправляет `Authorization: Bearer
<ключ>` на адрес противника. Либо `POST /api/mcp` регистрирует stdio-сервер с
произвольной командой. Владельцу для этого достаточно открыть вредную страницу
в обычном браузере при работающем контейнере.

### E. noVNC без пароля
`x11vnc -nopw`, `websockify` без проверки `Origin`. Порт 6080 на 127.0.0.1.
Любой процесс на Mac и, при отсутствии проверки Origin в websockify, возможно
веб-страница через WebSocket, получает интерактивный доступ к браузеру с
сессиями владельца. Требует проверки (см. «непроверенное»).

### F. Отравление журнала
Запись в `findings.md` с нужной противнику строкой `Источник:` внутри тела
подменяет источник в подвале отчёта. Журнал — вход проверочного прохода B, то
есть отравление попадает и в контроль.

## 5. Наиболее вероятные сценарии потери и искажения фактов

1. **Модель не записала находку.** Предохранитель ловит только «за шаг ноль
   записей» и только один раз за шаг (`manus.py:231-255`). «Записал три факта
   из десяти» не ловится ничем. Это признано и в справке.
2. **Отчёт режима «План» пишется мимо журнала** (`planning.py:_finalize_plan`).
   Самый тяжёлый случай: факты собраны, но в связный отчёт не попадают, а их
   место занимает то, что модель домыслила по списку пунктов.
3. **Подмена источника текстом в теле находки** — факт остаётся, ссылка врёт.
4. **Пересказ reader-моделью.** Рубеж 6: весь текст сверх 60k знаков проходит
   через flash-модель, и защита — три строчки промпта. Потеря здесь незаметна
   по построению (в отличие от обрезки, которая теряет предсказуемый хвост).
5. **Проверка B ловит только одно направление.** `app/prompt/verify.py:15-46`
   ищет утверждения отчёта без опоры в журнале. Обратное — записи журнала,
   которые в отчёт не попали, — не проверяется вообще. То есть **потеря
   структурно невидима для проверки**, ловится только выдумка.
6. **Проверка на той же модели.** Слот `verifier` пуст → `default`.
7. **Кодировка.** `_from_html` декодирует по заголовку HTTP, игнорируя
   `<meta charset>`. Страница в windows-1251 без charset в заголовке
   превращается в мусор с `errors="replace"`, и это выглядит как «на странице
   ничего нет», а не как ошибка.
8. **Арифметика.** Правило «считай кодом» — только промпт
   (`app/prompt/manus.py:99-119`, `planning.py:_step_rules`). Кодом не
   проверяется ничто: ни то, что число в отчёте совпадает с числом в журнале,
   ни то, что расчёт вообще выполнялся.

## 6. Наиболее вероятные сценарии провала добычи

1. **Сканированный PDF.** `_from_pdf` возвращает пустоту, OCR нет. Источник
   выглядит прочитанным.
2. **Кодировки** (см. выше).
3. **Пагинация и «показать ещё».** Ни `fetch`, ни `crawl` их не понимают;
   `crawl` идёт только по `<a href>` того же хоста, глубина ≤ 2, ≤ 60 страниц,
   бюджет 120 секунд.
4. **Бесконечная прокрутка** — только через `browser_exec`, вручную.
5. **Архивы.** `.zip` сохраняется, но ничем не распаковывается автоматически;
   рассчитано на то, что модель сама вызовет `subprocess unzip`.
6. **`.doc`/`.docx`** — сохраняются, но `_render` отдаёт «двоичные данные».
7. **Таймаут 25 с на запрос** без повторов — тяжёлый портал статистики
   отпадает молча (`ConnectError`/`TimeoutException` → строка в ответе).
8. **Антибот.** Правило «не ломись» разумно, но означает, что целый класс
   источников (доски объявлений с ценами) систематически выпадает, и вывод
   строится на том, что отдают добровольно. Это **смещение выборки**, а не
   просто пробел.
9. **Отсутствие ключа поискового API** → только скрейпинговые движки, которые
   сами упираются в антибот (`app/config.py:49-55` прямо об этом пишет).

## 8. Что в этой модели угроз намеренно НЕ считается риском

* Доступность из локальной сети — порты привязаны к 127.0.0.1, проверено.
* Попадание ключей в образ Docker — `.dockerignore` корректен, проверено.
* Секреты в истории git — не найдены, проверено.
* Многопользовательские сценарии — пользователь один.
* Юридические вопросы — по условию аудита вне области.
